# Doxygen sites

For C and C++ (and other) API references generated by Doxygen: pages named
like `group__window.html` or `classfoo_1_1_bar.html`, a "Generated by
doxygen" footer. `detect` prints the SOURCE: the folder of the Doxygen HTML
(a site URL or a local `html/` output folder). A page URL works too. Sites
that publish Doxygen through Sphinx (Breathe, Exhale) serve `objects.inv`
and are built as `sphinx`.

`detect` also prints which index the site has:

- `index: search`: the client-side search index (`search/*.js`). A few
  dozen to a few hundred small files.
- `index: menu`: no search index (the site searches on its server), so
  `plan` reads `menudata.js` and Doxygen's index pages (class list, files,
  groups, member and global indexes). `plan` prints `reading N Doxygen
  index pages` first: on a large site that is a few hundred requests at the
  polite rate.

## The loop

1. `plan SOURCE --name NAME` reads the index, writes the plan and prints a
   summary: pages kept in full, pages made stubs, and the entries per type
   (Function, Class, Struct, Macro, Type, Enum, Constant, Module, ...).
2. Check the summary. Pages that document members (group/module pages,
   class and struct pages, headers that document their own macros) are
   kept in full; prose pages (guides, "related pages") become stubs that
   link to the live page. Source listings, markdown-source pages
   (`*_8md.html`), directory pages and the index pages themselves are left
   out. Change a choice with `--full PAT` / `--stub PAT` (shell globs on
   page names, e.g. `--full 'window_guide'`, `--stub 'group__deprecated*'`).
3. `build NAME` fetches the full pages (one request at a time, robots.txt
   honoured) and writes the docvol. A page that fails becomes a stub with
   the error.
4. Look things up with docshelf: `search glfwCreateWindow -d NAME`,
   `show NAME:group__window#ga...`. Class members are named
   `Class::member`; C functions, macros and globals keep their bare names.

`build SOURCE --name NAME [plan options]` does 1 and 3 in one step. A
rebuild (`build NAME`) reads the index again; if it changed, the plan is
redone with the same overrides.

Projects split into several Doxygen sites (Arm CMSIS has Core, Driver,
RTOS2, DSP, ...) are built one docvol per site:
`build https://docs.example.org/cmsis/Core/ --name cmsis-core`.

## When it goes wrong

- `the site may be blocking automated requests`: an index file came back
  as an HTML page (a bot check). Try later or from another network; a
  local copy of the HTML output works as SOURCE.
- Warnings such as `search/functions_3.js: missing` name index files that
  could not be read; the rest are still used. If none can be read, exit 3.
- `search index not readable (...), using the index pages`: an older or
  unusual search-index format; the build continues from `menudata.js`.

Exit code 3 means the site has a Doxygen index that could not be read (no
entries in any index file).
