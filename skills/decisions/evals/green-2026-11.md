## New failures found and fixed (REFACTOR)

1. **Setup file in the wrong shape** (S1a, S3a, S3b, S5a): `questions` as a
   list with `id`/`text`, `policy.good_if` as free text. Fix (structural):
   `load_setup` validates the shape and names the problem; `SKILL.md` step 2
   says to start from `examples/lead-vetting.decisions.json` and check with
   `run --dry-run`.
2. **Flagging logic inverted for moderation** (S4a, S4b): with the default
   combination, a low spam score rejects a post that scored high on
   harassment. S4a noticed and worked around it with one gate question. Fix:
   `policy.combine: "any"` (pass = flagged if any rule passes), documented in
   `SKILL.md` step 6 and `setup-file.md`.
3. **Per-turn options** (S3a): legal moves change every turn. `SKILL.md` step
   7 now says questions can be built per call with fixed names and rules.

Not a skill problem: S5a/S3a mentioned the local environment's routine by
name in "what next" (environment bleed); one run had a Bash read denied by
the harness classifier.
