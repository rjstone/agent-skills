# docshelf 0.7.3 design: group 6 design items

Short design (a small change set). Status: draft for the user's approval.

## Intent

docshelf should hold up under real use: a damaged docvol, an agent driving it
over MCP, parallel subagents writing notes for the same docvol. All items are
fixes, so this is a patch release: 0.7.3 (SKILL.md `metadata.version` and
`shelf_core.VERSION` move together). One PR from `update/docshelf`.

Non-goals: no new commands or flags, no locking subsystem, no change to the
on-disk cache format. Anti-goal: rewriting quoted documentation text in
output (a hint rewrite must never touch doc text).

## Items and decisions (the user, 2026-11-17)

### 6.9.2 Notes: retry when another writer got there first

Who writes at once: parallel subagents annotating one docvol (the user).
Today `--set`/`--delete` read the whole file, edit one section and replace
the file atomically, so two writers editing different sections lose one edit
silently.

Approaches: (A, picked) compare content: keep the bytes read at the start;
just before `os.replace`, read the file again; if it changed, apply the same
`--set`/`--delete` to the new text and retry, up to 3 tries in total, then
exit 2 with "notes changed by another writer; not written". (B) compare
mtime and size: cheaper but FAT and some network shares keep mtime at 1-2 s,
and subagents write within the same second. (C) a lock file: rejected by
the user as more than needed.

Notes: a file that did not exist and now does counts as changed. The window
between the re-read and the rename remains (microseconds instead of the
whole edit); say so in a code comment. CRLF handling and the size check run
on each retry's result.

### 6.13.25 One unreadable docvol stops every multi-docvol command

One sensible way: a shared helper (e.g. `for_each_docvol(docs, named)`)
used by every multi-docvol loop: search (entries and headings), types, fts
and suggest. A docvol failing with a code-5 `CLIError` is skipped with a
`warning:` naming it and the reason, unless it was named with `-d`, which
still exits 5. When every selected docvol fails, exit 5. Each broken docvol
is warned about once per command.

### 6.13.12 CLI wording over MCP

Approaches: (A, picked) docshelf's own hint lines in stdout go through one
`hint()` helper that, under MCP, passes them through `explain()`; and
`explain()` runs on all captured stderr (stderr never carries doc text).
(B) stderr only: leaves the search/toc hints in stdout in CLI wording.
Covers at least: `raise --max-lines ...`, `-d NAME picks one`,
`show REF opens`, the catalog note naming `assets/allowlist.txt`.

### 6.13.18 Stale-temp sweep vs a live temp

Approaches: (A, picked) close with a comment in `sweep_stale_tmp`: a temp
being written keeps a fresh mtime, so only one idle for over an hour is
swept. (B) pid-stamped names, skip temps with a foreign pid under 24 h:
more code, and pid liveness is unsafe on Windows (`os.kill(pid, 0)`
terminates the process there). Mark the TODO item done as won't-fix.

### 6.13.21 `ids` term for `printf(3)` / `vector<int>`

Skip the `ids:` alternative when the token's core is not an identifier
(`_IDENT_RE.fullmatch` fails); the text phrase match already finds these.
