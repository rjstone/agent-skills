# docshelf 0.5.0: tag-safe stripping, toc, types, offsets, notes writes, fts identifiers

Status: approved by the user (2026-11-17). Skill: `skills/docshelf/` (0.4.0
on `main`). Items from TODO.md's docshelf list: 3.1, 1.1, 1.2, 1.3, 1.4,
1.6, 4.1, 4.4.

## Intent

Make lookups cheaper and safer for agents (especially small models):
an outline before reading (`toc`), a quick picture of a docvol (`types`),
paging through long sections (`--offset`), notes an MCP client can write,
better full-text search for code identifiers, and no way for page cleanup
to blank a whole page.

## Approaches

- 3.1: (a, chosen by the user) keep class/role/`hidden` skipping but never
  for the page structure (`html`, `body`, `main`, `article`); (b) drop
  class-based skipping and rely on tags plus repeated header/footer
  stripping: rejected, it brings Sphinx sidebars and breadcrumbs back.
- 4.1: (a, chosen) a second FTS column with identifiers kept whole plus
  camelCase pieces, and an any-word retry when all-words finds nothing;
  (b) a custom tokenizer: not possible from Python's stdlib sqlite3.
- 1.6: (a, chosen) `notes --set HEADING --text TEXT` / `--delete HEADING`
  on the shared command table, so CLI and MCP get both; (b) an MCP-only
  write tool: rejected, two interfaces.

## Design (as decided)

- **3.1** `shelf_render`: class names in `SKIP_CLASSES`, roles in
  `SKIP_ROLES` and the `hidden` attribute never skip `html`, `body`,
  `main` or `article`; tag-based skipping (`SKIP_TAGS`) is unchanged.
- **1.1** `toc REF`: page title line, then one line per heading of the
  page REF points into (the whole page, not just the section), indented
  two spaces per level below the top level, each followed by the REF that
  `show` takes. `--max-lines` caps it (default 150). CLI and MCP.
- **1.2** `types [-d NAME...]`: per docvol, `NAME` then one line per entry
  type, most common first: `  <count>  <type>`. Uses the normal scope rules.
- **1.3** `show --offset N`: skip the first N lines of what `show` would
  print (after `--grep`). When the cap cuts, the cut line names the next
  offset: `... 240 more lines; --offset 150 continues (or --full)`.
- **1.4** `install` with no names: install the project file's `"docvols"`
  entries that resolve to DevDocs rows and aren't installed; skip ones that
  are installed or are docsets (named in one line each); keep the
  redundancy refusal and `--force`. No names and no project list: exit 2
  with a hint.
- **1.6** `notes NAME --set HEADING --text TEXT` adds or replaces the
  `## HEADING` section (typed headings like `## f (Function)` match
  exactly); `notes NAME --delete HEADING` removes it. Writes are atomic,
  create the file (and folder) when missing, refuse (exit 2, file
  unchanged) when the result would break the size limits, and print the
  `--check` result. Agents may write notes without asking (the user,
  2026-11-17).
- **4.1** The FTS index gains an `ids` column: identifiers from the page
  text kept whole (`return_exceptions`, `getElementById`, `os.path.join`
  parts) plus their camelCase pieces. Matching searches both columns;
  snippets come from `text`. A multi-word query with no all-words hit
  retries with any-word matching and prints `note: no page has all the
  words; showing pages with any of them`. `FTS_FORMAT` bump.
- **4.4** `fts --max-lines` below 3 never prints more than the cap.
- Version 0.5.0 (features); help, SKILL.md and references updated; TODO
  items removed.

## Constraints

As in the 0.4.0 design: stdlib only, Python 3.9+, never write into a
docset folder, no network on lookups, `shelf_core` imports no backend,
tests hermetic, public-repo rules, tests read `shelf_core.VERSION`.

## Left to the builder

Internal function names beyond those the plan fixes; exact help wording in
the existing style.
