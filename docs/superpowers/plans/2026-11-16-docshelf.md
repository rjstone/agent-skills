# docshelf Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A stdlib-only CLI skill, `docshelf`, that installs DevDocs docsets and looks them up offline (search, show, fts, notes) with dash-docset's trial-tuned interface, plus a secondary `--mcp` stdio server on the same command table.

**Architecture:** A front end lifted from dash-docset (help, REFs, scorer, renderer, `--grep`, FTS5, notes) works on docsets only through a small `Docset` interface; the DevDocs backend implements it over the cache layout devdocs-mcp used, with a byte-offset page index so a one-shot CLI never parses a whole `db.json`. The MCP layer runs the same command functions and returns their stdout.

**Tech Stack:** Python 3.9+ stdlib (`argparse`, `json`, `sqlite3` with FTS5, `html.parser`, `urllib.request`), `unittest`.

**Spec:** `docs/superpowers/specs/2026-11-16-docshelf-design.md`

**Source to lift:** dash-docset's script and tests, read with
`git show origin/skill/dash-docset:skills/dash-docset/scripts/docset.py` and
`git show origin/skill/dash-docset:tests/test_dash_docset.py` (fetch first:
`git fetch --depth=50 origin skill/dash-docset`). Line numbers below refer
to that `docset.py` at `1058b98`. Lift and adapt; don't rewrite what works.
Never write the name "dash-docset" into any file under `skills/docshelf/`.

## Global Constraints

- Stdlib only, no install step; Python 3.9+; Linux, macOS and Windows.
- `SKILL.md` frontmatter exactly per `AGENTS.md` ("Skill frontmatter"):
  `name: docshelf`, single-line `description` starting "Use when",
  `compatibility` (network for install only; FTS5), `license: MIT`,
  `metadata.author: Robert Stone`,
  `metadata.source: https://github.com/rjstone/agent-skills`,
  `metadata.version: "0.1.0"`,
  `metadata.credits: "DevDocs, devdocs-mcp, Zeal"` (names only; links go in
  the body's `## Credits`; the user, 2026-11-16).
- Scripts are invoked as `python scripts/docshelf.py` (paths relative to the
  skill folder); the entry point adds its own folder to `sys.path`.
- Cache: `DOCSHELF_CACHE_DIR`, else `~/.cache/docshelf/`, on Windows
  `%LOCALAPPDATA%\docshelf\cache\`. DevDocs files under `<cache>/devdocs/`:
  `docs.json`, `<slug>/index.json`, `<slug>/db.json`, `<slug>/meta.json`
  (`{slug, name, release, mtime, installedAt}`, plus `alias`); derived files
  in `<cache>/devdocs/<slug>/.docshelf/`.
- Notes: `DOCSHELF_NOTES_DIR`, else `$XDG_DATA_HOME/docshelf/notes/`
  (default `~/.local/share/docshelf/notes/`), on Windows
  `%APPDATA%\docshelf\notes\`; file `<family>.md`, family = slug before `~`.
- Project file: `.docshelf.json` with an optional `"docsets"` list.
- REF = `<docset name>:<backend part>`; split at the first `:`. DevDocs:
  `<slug>:<path>[#anchor]`.
- Exit codes: 0 ok; 1 `notes --check` problems; 2 usage, unknown name or no
  FTS5; 4 scope too wide; 5 not found; 7 network. 3 is reserved, unused.
- Hosts: `devdocs.io` (manifest, 302 redirect, needs a User-Agent) and
  `documents.devdocs.io`. No network on lookups; manifest cached 24 h.
- No network in tests; tests in `tests/test_docshelf.py`, starting with
  `if not selected("docshelf"): raise unittest.SkipTest(...)`.
- Public repo: no account names, home paths or secrets (`AGENTS.md`).
- Never `json.load` a whole `db.json` outside install and page-index
  builds.

## Review Focus

1. A `db.json` whose HTML has non-ASCII text, escaped quotes and
   backslashes: every page read through the byte-span index equals
   `json.load(db)[key]` (Task 2).
2. A docset installed by another tool (no `.docshelf/`), or whose `db.json`
   changed after the page index was built: lookups rebuild the index and
   return the new text, never stale or garbled spans (Task 2).
3. Two releases of one family installed (`python~3.13`, `python~3.14`):
   `-d python` exits 2 naming both slugs; `-d py` (alias) does the same;
   both releases share `notes/python.md` (Tasks 2, 6).
4. Network down or interrupted: a stale cached manifest is used with a
   stderr note; with none, exit 7 naming the two hosts; a failed download
   leaves no half-installed docset (`meta.json` written last) (Task 8).
5. Bad MCP input (a non-JSON line, an unknown tool, missing required
   argument): a JSON-RPC error or `isError` result, and the server keeps
   serving the next request (Task 10).
