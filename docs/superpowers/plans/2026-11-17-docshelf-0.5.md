# docshelf 0.5.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Tag-safe page cleanup, `toc`, `types`, `show --offset`, `install` of the project list, notes writes (CLI and MCP), identifier-aware `fts`, and the `fts --max-lines` fix.

**Architecture:** Each feature is a small change on docshelf's shared command table (`shelf_cli.COMMANDS`), so the CLI and the `--mcp` server get it together. Rendering, lookup, install and notes code stay in their modules.

**Tech Stack:** Python 3.9+ stdlib, `unittest`.

**Spec:** `docs/superpowers/specs/2026-11-17-docshelf-0.5-design.md`

## Global Constraints

- Stdlib only; Python 3.9+; `shelf_core` imports no backend module.
- Never write into a Dash, Zeal or other docset folder; no network on lookups.
- Tests are hermetic (use `clean_env`, `run_cli`, the module-level env patch in `tests/test_docshelf.py`); this sandbox has a real Zeal installed that tests must not see.
- No account names, home paths or drive-letter paths in committed files.
- Tests read `shelf_core.VERSION`, never a literal; the version becomes `"0.5.0"` only in Task 9.
- Every new command or flag goes through `shelf_cli.COMMANDS` so MCP gets it; when the top-level help changes, `TOP_HELP_EXPECTED` changes in the same commit.
- Commit trailer lines: `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` and `Claude-Session: https://claude.ai/code/session_01QT6szwNZv31dTM16LMHNJr`.

## Review Focus

1. A page whose `<body>` (or `<main>`/`<article>`) carries a skip class, skip role or `hidden`: content still shown. (Task 1)
2. `show --offset` past the end: a clear one-line message, exit 0, nothing else printed. (Task 4)
3. `notes --set` with text containing a `## ` line: refused (exit 2) so one write can't create or clobber other sections. (Task 7)
4. `fts` on a query of identifiers with punctuation (`os.path.join`, `std::vector`): no FTS5 syntax error; finds the page. (Task 8)
5. `install` with no names and a project list naming a docset family and an unknown name: the docset is skipped with a line, the unknown name is reported, others install. (Task 6)

### Task 7: Writing notes (1.6)

**Files:** Modify `shelf_notes.py` (`cmd_notes`, new `set_section`, `delete_section`), `shelf_cli.py` (`--set`, `--text`, `--delete` on `notes`), `skills/docshelf/references/notes.md` (how to write over MCP/CLI), tests (class `NotesWriteTests`).

**Interfaces:**
- `set_section(text: str, heading: str, body: str) -> str` and `delete_section(text: str, heading: str) -> str`: pure functions on the notes file text; a heading matches a `## ` line exactly after stripping (typed headings included); `set` replaces the whole section body or appends `## heading\n<body>\n` at the end; `delete` of a missing heading raises `CLIError(... , 5)`; `heading` "General" addresses the general section.
- `notes NAME --set H --text T`: `--text` required with `--set`; T containing a line starting `## ` → exit 2; result exceeding `NOTES_*_MAX` (per `size_warnings`) → exit 2, file unchanged; else atomic write (temp + `os.replace`), creating the notes folder, then print `--check` output and return its code.
- `notes NAME --delete H`: same write path.

### Task 8: `fts` finds code identifiers (4.1)

**Files:** Modify `shelf_lookup.py` (`build_fts` schema and text, `fts_match_expr`, `fts_search`, `cmd_fts` note, `FTS_FORMAT` +1), tests (class `FtsIdentifierTests`).

**Interfaces:**
- Index: `pages` gains column `ids` (after `text`): for the page text, every identifier-like token `[A-Za-z_][A-Za-z0-9_]*(?:[.:]+[A-Za-z_][A-Za-z0-9_]*)*` with `_`, `.` and `::` replaced by nothing-but-kept-whole (store `return_exceptions` as `returnexceptions` AND the original pieces is NOT needed: store each identifier with separators removed, lowercased) plus camelCase pieces joined (`getElementById` → `getelementbyid`); one space-separated string per page.
- Query: each query token becomes `("tok" OR ids:"<joined form>")` when the token is identifier-like, else `"tok"`; tokens with no word characters are dropped (all dropped → "no searchable words in QUERY", exit 0 with that line). Snippets still from `text` (column 1).
- Any-word retry: when all-words (AND) returns nothing and the query has 2+ tokens, rerun with OR and print `note: no page has all the words; showing pages with any of them` first (stderr with `--json`).

- [ ] Step 1: failing tests: `test_identifier_with_underscore_ranks_first` (page A contains `return_exceptions`, page B "return ... exceptions" far apart: A first); `test_camelcase_identifier` (`getElementById` query finds the page); `test_dotted_identifier` (`os.path.join`); `test_punctuation_only_query`; `test_any_word_retry_note`; `test_existing_index_rebuilt` (an index with the old `FTS_FORMAT` stamp is rebuilt).
- [ ] Steps 2-5: RED, implement, full suite, commit `docshelf: fts matches code identifiers whole and retries with any word`.
