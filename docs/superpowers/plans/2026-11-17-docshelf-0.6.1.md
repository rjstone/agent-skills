# docshelf 0.6.1 (bug fixes) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix the user-facing docshelf bugs in TODO.md items 6.11.1,
6.9.1, 6.11.2, 6.8.5, 6.2.7, 6.2.3, 6.2.1, 6.1.1, 6.7.2, 6.7.5, 6.12.4.

**Architecture:** Each fix stays in the module that owns the behaviour;
no new modules. Each task: failing test first, then the fix.

**Tech Stack:** Python 3 stdlib, `unittest`.

**Spec:** TODO.md, `### docshelf`, the items above (their text is the bug
report) plus the decisions below. No separate design doc: these are bug
fixes whose expected behaviour is stated here (the user, 2026-11-17:
"Start PR 1").

## Global Constraints

- Stdlib only. Version 0.6.1 in `SKILL.md` `metadata.version` and
  `shelf_core.VERSION` (patch: script fixes, no features), set in Task 6.
- Tests in `tests/test_docshelf.py`, hermetic (`clean_env()`, `run_cli()`,
  `make_devdocs`, `make_docset`, `row`, `FakeNet` for network), no real
  network.
- Full suite from the repo root: `python3 -m unittest discover -s tests`
  (483 pass before this work).
- Public repo: no names, hostnames or absolute home paths.
- Don't change behaviour beyond each item; existing tests keep passing
  unless the item itself changes that behaviour (then update the test and
  say so).

## Decisions

- 6.12.4 (the user, 2026-11-17): a lower bound pins the minimum
  (`django>=3.2` -> `django~3.2`), because code using newer features
  wouldn't work where only the minimum is installed. Current behaviour;
  lock it with a test and say so in `references/getting-docvols.md`.
- 6.9.1 lock against concurrent writers: out of scope (writes are already
  atomic via temp file + replace; last writer wins). Keep that part in
  TODO.md as 6.9.2.
- Error output: follow each command's existing style (stderr notes,
  `CLIError(message, code)`, exit codes listed in `shelf_cli.EXIT_CODES`).

## Review Focus

1. Notes files with CRLF endings: every write keeps CRLF (Task 1).
2. `install` with no NAME and three project docvols where the 2nd fails:
   the 1st and 3rd install, the failure is reported, exit non-zero
   (Task 3).
3. `--json` modes never print plain text on stdout (Task 2).
4. A Zeal catalog with one malformed entry among good ones still lists the
   good ones (Task 5).
5. Links like `foo.html?x=1#bar` and `foo%20bar.html` resolve (Task 4).

### Task 1: Notes writes are safe (6.11.1, 6.9.1)

**Files:** `skills/docshelf/scripts/shelf_notes.py` (`_write_notes` ~375,
`delete_section` ~358, the `--set` path, CRLF normalization ~285);
`tests/test_docshelf.py` (`NotesWriteTests`).

- 6.11.1: a dangling symlink at the notes path: refuse the write with a
  `CLIError` naming the path (exit 2), never create the link's target or
  its folder. A symlink to an existing file: unchanged behaviour.
- 6.9.1 a: `--set HEADING` matches an existing heading case-insensitively
  (as display does): `--set Foo` replaces `## foo` (keeping the file's
  existing heading text), not appends a duplicate. Same for `--delete`.
- 6.9.1 b: a write keeps the file's line endings: a CRLF file stays CRLF.
- 6.9.1 c: deleting an unheaded General section leaves one blank line
  between the title and the next heading.
- Tests: one per point, exact file contents asserted.
- Move the lock part of 6.9.1 to a new TODO item 6.9.2 in Task 6 (not
  here).

### Task 2: CLI output fixes (6.11.2, 6.8.5)

**Files:** `shelf_lookup.py` (`cmd_fts` ~545, `cmd_toc` ~239); tests
(`FtsTests`, `TocTests`).

- 6.11.2: `fts --json` with no searchable words prints valid JSON on
  stdout (`[]`, the same shape as no hits) and the message on stderr;
  exit code unchanged.
- 6.8.5: `toc REF#missing` warns on stderr exactly like `show`
  (`warning: no #<anchor> on <page>`) and prints the whole page's toc; a
  page with no headings prints its title line plus
  `(no headings)`.
- Tests: assert stdout parses as JSON; assert the warning text; assert the
  no-headings output.

### Task 3: DevDocs install and sources (6.2.7, 6.2.3, 6.2.1)

**Files:** `shelf_devdocs.py` (`cmd_install` ~560, `fetch`/`NetError`
~231-270, `cmd_sources` ~471); tests (`NetworkTests` with `FakeNet`).

- 6.2.7: `install` (with or without names) continues after a failed
  download, prints each failure, and exits with the first failure's code
  at the end. A redundancy refusal (documentation already on disk as a
  docset) is a skip with a note, not a failure: exit 0 if nothing else
  failed.
- 6.2.3: an HTTP 404 from documents.devdocs.io says the documentation
  wasn't found on DevDocs (name the slug) without the allowlist hint;
  other network errors keep the hint (exit 7). A 404 is "not found":
  exit 5.
- 6.2.1: `sources` lists each slug once (keep the first row).
- Tests: three-name install with the middle one failing; a 404 message
  and exit 5; duplicate slug rows in the manifest listed once.

### Task 4: Links with a query or percent-encoding (6.1.1)

**Files:** `shelf_core.py` (`resolve_doc_path` ~273, `Docvol.resolve_href`);
tests.

- Strip `?query` from the path part before resolving; percent-decode each
  path segment (`foo%20bar.html` -> `foo bar.html`) before the
  known-pages check; keep the fragment as is (anchors are decoded at
  match time).
- Tests: on a DevDocs docvol and a docset page, a link
  `other.html?x=1#sec` and a link `my%20page.html` get REFs.

### Task 5: Dash/Zeal catalogs (6.7.2, 6.7.5)

**Files:** `shelf_dash.py` (catalog code ~778-930); tests (catalog tests
with `FakeNet`).

- 6.7.2: one malformed entry (or malformed `versions`) skips that entry
  only; a note says how many entries were skipped.
- 6.7.5: when a refetch of an expired catalog fails, use the stale cached
  copy with a note naming its date (as `get_manifest` does for DevDocs).
- Tests: malformed entry among good ones; expired cache + network error.
