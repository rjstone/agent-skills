## Decisions

- Version: minor (0.7.0). `initialize` instructions and batch support are
  new protocol features; AGENTS.md: a skill with scripts takes a minor
  bump for new features.
- 6.3.3: MCP forbids a null request id. A message with `"id": null` gets
  error -32600 "invalid request" (id null in the reply), not a result.
- 6.3.4: accept a JSON array of messages for every negotiated version
  (harmless for 2025-06-18, which dropped batching; required for
  2025-03-26, which we advertise). Reply with an array of the non-null
  replies in order; no output when all are notifications; an empty array
  is one -32600 error. `initialize` inside a batch is allowed (no special
  case).
- 6.3.2: `initialize` returns `instructions`: a short plain-text guide
  (under ~600 characters) on how to use the tools: `search` then `show`
  the REF, `fts` for words in page text, `toc` for long pages, scope with
  `docvols` or `-d`-equivalent argument, `suggest` for a project's
  docvols, notes for lessons. Exact wording is the implementer's; keep it
  in one module constant.
- 6.3.1: error text reaching MCP callers names tools and their argument
  names, never `docshelf.py ...` or CLI flags. Do it in `explain()` (one
  place), mapping: `docshelf.py <cmd>` -> "the `<cmd>` tool"; a CLI flag
  (`-d`, `--all`, `--force`, `--set`, ...) -> its tool argument name
  (`_prop_name`), derived from the `COMMANDS` table, not a hand list where
  avoidable. Bare CLI phrases like "sources QUERY" -> "the `sources`
  tool". CLI output is unchanged.
- 6.3.5: no argparse private attributes. `shelf_cli` gains one function
  that returns each command's parameter defaults from the `Param` table
  (the same values `_add_param` gives argparse); `_parser_defaults` uses
  it. A test proves it equals what argparse produces for every MCP
  command (via public `parse_args` with the required positionals filled
  in).
