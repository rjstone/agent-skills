# docshelf 0.7.3 (group 6 design items) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close TODO.md `### docshelf` items 6.9.2, 6.13.12, 6.13.18,
6.13.21, 6.13.25 and 6.13.26-30 as designed in the spec.

**Architecture:** No new modules. One `CLIError` subclass for a damaged
docvol, one skip helper used by every multi-docvol lookup, one `hint()`
pass-through that MCP points at `explain()`, and a compare-and-retry
around the notes write. Tests go in `tests/test_docshelf.py`.

**Tech Stack:** Python 3 stdlib, `unittest`.

**Spec:** `docs/superpowers/specs/2026-11-17-docshelf-0.7.3-design.md`
(read it first), plus the TODO.md text of each item a task names.

## Global Constraints

- Stdlib only. Version **0.7.3** (patch) in `skills/docshelf/SKILL.md`
  `metadata.version` and `shelf_core.VERSION`, set in Task 5 only.
- CLI output must not change except where an item says so.
- Tests hermetic: `temp_env`, `clean_env()`, `run_cli()`, `make_devdocs`,
  `make_docset`; no network. Test output pristine (capture stderr).
- Full suite from the repo root: `python3 -m unittest discover -s tests`
  (653 pass before this work).
- Public repo: no names, hostnames, home paths or drive-letter paths, in
  plans and tests too. Never hand-edit `skills/index.json`.
- Subagents never call session, archive, scheduling, trigger or
  environment tools, and never dispatch subagents.

## Decisions (the user, 2026-11-17)

- 6.9.2: content compare-and-retry (spec option A), 3 tries in total, then
  exit 2 `notes changed by another writer; not written: PATH`. No lock.
- 6.13.25: skip and warn a damaged docvol unless the user passed `-d`
  (any `-d`, even one that names a family of several: strict). All
  selected docvols damaged: exit 5. Skipping is the whole recovery for
  now; better recovery is TODO 6.14 (already on `main`).
- Every damaged-docvol error and skip warning carries repair advice:
  DevDocs `repair with: docshelf.py remove NAME, then docshelf.py install
  NAME`; docset `reinstall it in Dash or Zeal`.
- Builder's call (flagged in the spec): a damaged docset *index* exits 5,
  not 7. Archive (tarix) read errors stay 7.
- 6.13.12: spec option A (`hint()` for stdout hints, `explain()` on all
  stderr). 6.13.18: comment only, item closed won't-fix. 6.13.21: skip
  the `ids:` term for non-identifier tokens.

## Review Focus

1. `--json` with a skipped docvol: the warning goes to stderr; stdout
   stays one valid JSON document (Task 1 test).
2. Upgrade from an old cache: a damaged DevDocs docvol whose meta.json has
   no `entry_count` (discovery skips it) and one that has it (lookup
   fails later) each give exactly one warning, never zero or two
   (Task 1 test).
3. Long-running MCP server: the hint rewriter is active only inside a
   tool call; CLI code run afterwards in the same process prints CLI
   wording (Task 3 test).
4. `-d FAMILY` that expands to several docvols, one damaged: exit 5, not
   a skip (Task 1 test).
5. Notes: the other writer deleted the file between read and write:
   `--set` recreates it with only our section; `--delete` exits 5
   `no notes file yet` (Task 2 test).

### Task 2: Notes compare-and-retry (6.9.2)

**Files:**
- Modify: `skills/docshelf/scripts/shelf_notes.py:393-455` (`_write_notes`,
  `_write_request`, the call in `cmd_notes`)

  writers are safe; a 4th conflicting write in a row gives exit 2)
- Test: `tests/test_docshelf.py` (new class `NotesRetryTests`)

**Interfaces:**
- Produces: `_write_notes(path, text, expect=_NO_CHECK)`: after writing the
  temp and before `os.replace`, if `expect is not _NO_CHECK` and
  `_read_notes_strict(path) != expect`, discard the temp and raise
  `NotesChanged` (module-private exception).
- Produces: `_write_request(cfg, args, path) -> str`: reads with
  `_read_notes_strict`, applies `--set`/`--delete`, writes with
  `expect=<text read>`; on `NotesChanged` starts again from a fresh read,
  `NOTES_TRIES = 3` attempts in total, then
  `CLIError("notes changed by another writer; not written: %s" % path, 2)`.
  Validation errors (`--set` with `--delete`, etc.) are raised before the
  first read, as today.

- [ ] **Step 1: Write the failing tests.** Simulate the other writer by
  wrapping `shelf_notes._read_notes_strict` with `unittest.mock.patch`
  so the re-check call writes the file first (in-process via
  `shelf_notes.cmd_notes` or the existing in-process notes helper).
  - `test_concurrent_set_keeps_both`: other writer adds `## B` between our
    read and write of `## A`; final file has both sections.
  - `test_gives_up_after_three`: other writer changes the file on every
    re-check: exit/`CLIError` code 2, message
    `notes changed by another writer; not written`, file holds the other
    writer's last text.
  - `test_file_appeared`: no file at start, other writer creates one:
    retried, both sections present.
  - `test_file_deleted_set_and_delete`: other writer deletes the file:
    `--set` leaves a file with only our section; `--delete` gives code 5
    `no notes file yet`.
  - `test_crlf_kept_on_retry`: other writer's file is CRLF; result is CRLF.
  - `test_replace_permission_error`: patch `os.replace` in `shelf_notes`
    to raise `PermissionError` (Windows: another process has it open):
    code 2 `cannot write`, no traceback, no temp left.
